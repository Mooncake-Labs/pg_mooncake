# Known failures of scripts/e2e-smoke.sh on this branch with its submodules (moonlink v0.3-dev
# 0e38b435; pg_duckdb v1.0.0-mooncake 12b6de7).
#
#   bug <name> class=blocking|class=limitation <description>
#   check <scenario.check> <bug> <regex>
#   requires <scenario.check> <bug> <earlier scenario.check> <bug2>
#
# class=blocking: the bug can crash-loop moonlink, panic, lose or silently change mirrored data, or
# make mirrors unusable. It must be fixed before a release; while one is listed the gate can't pass,
# and a check that fails with it fails the gate.
# class=limitation: a documented, loud or harmless restriction that ships in the release notes. A
# check that fails only with limitations reports XFAIL(limitation:<bugs>) and doesn't fail the gate.
# A bug may be declared only once.
#
# A listed check reports XFAIL(<bug>) only when each of its failure signatures matches the regex
# (bash ERE) of one of its listed bugs; any other failure is a plain FAIL. A check may list several
# bugs, one line each. Bug names use only [A-Za-z0-9_.-]. Signatures, one per line:
#   most checks                   the RESULT detail
#   no_moonlink_panics            "<file>:<line> x<n>" per panic location
#   bgworker_no_abnormal_exits    "exited with exit code <c> x<n>", "was terminated by signal <s> x<n>"
#   no_postgres_crash_restarts    "<kind> terminated by signal <s> x<n>", "<kind> exited with exit code
#                                 <c> x<n>", "reinitializing x<n>", "abnormal shutdown x<n>", and
#                                 "server process crashes not reported by a session check x<n>"; <kind>
#                                 in PostgreSQL 17 terms
#   no_worker_errors_*            "<file>:<line>: <innermost cause> x<n>", or "error: <text> x<n>" for
#                                 an ERROR or FATAL without a source location (log prefix removed,
#                                 absolute paths shortened)
#   main.drop_all_files_removed   the whole leftover listing on one line: "<type> pg_mooncake/<path>"
#                                 per entry, type as find's %y (d directory, f file, ...)
#   session checks (config_reload, mirror_writes, roles), one of
#                                 "backend crashed (<kind>, <signal s | exit code c>,
#                                   cassert=<yes|no|unknown>) running [<statement>]; TRAP: <assertion
#                                   or none>", <kind> in PostgreSQL 17 terms ("server process" for any
#                                   backend, also on 18)
#                                 "session lost its connection, but no crash was logged: <stderr>"
#                                 "unexpected output: [<stdout>] stderr: [<stderr>]"
#                                 "unexpected stderr: [<stderr>] output: [<stdout>]"
# A "requires <check> <bug> <earlier check> <bug2>" line makes the check's <bug> rule count only if
# the earlier check failed with <bug2>, for failures whose text alone doesn't name the cause (a hung
# DROP, a missing fence mirror). Panic sites are pinned to file:line per moonlink revision.
